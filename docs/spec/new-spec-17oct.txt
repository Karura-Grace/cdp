#Heading1 0. About This Document
#Heading2 0.1 Purpose
This document is the single, final build baseline for the CDP platform. It converts the CDP instrument, its scoring rules and its advisory method into a specification precise enough to code from, while preserving the advisory meaning a PAC consultant must be able to defend in a boardroom. Every rule in it is authoritative as written: it states what the platform does, not what it might do. Developers code from this document; testers test against it; PAC faculty change advisory logic only through the versioned rules and reference data it describes.
Part A specifies the platform. Part B incorporates the CDP Action Planning Guide as a tagged reference library, and specifies the report composition engine that uses it to write complete reports with suggestions fitted to each organisation, so that one document carries the scoring, the advice and the reporting together.

#Heading2 0.3 How to read it
Each section is written for two readers. Subsections headed “Logic” give developers exact, testable rules: formulas, thresholds, boundary conditions and error behaviour. Subsections headed “Advisory meaning” give consultants the interpretation that must accompany the number when it is presented to a client. Where the two diverge, the advisory meaning constrains how the number may be displayed; it never changes the calculation.
Notation: D1–D9 for the nine CDP dimensions, S1 · S2 · S3 for scenario position within a dimension, C1–C4 for the four alignment checks, eOS Q1–Q8 for the eight employee-survey categories, TPS for the Transformation Probability Score and LRI for the Leader Readiness Index. Figures are drawn in the CDP visual language used in client material; every figure that shows numbers uses the illustrative worked example (2.4.1, 11.11) and is labelled as such.
#Heading2 0.4 Intellectual property position
The four CDP orientations (ENGAGE, INNOVATE, PERFORM, GOVERN), the nine dimensions, the scenario statements, the scoring architecture, the alignment checks, the orientation playbooks and all tooling described here are Priority Activator Consulting’s own development. This document and the platform make no reference to, and take no naming, structural or descriptive content from, any third-party culture framework, diagnostic instrument, quadrant taxonomy, survey methodology or brand. The orientation map is described solely in PAC’s own terms (inward or outward focus; adaptive or structured stance). Metrics use PAC terminology throughout: the eOS respondent bands are Advocates, Neutrals and Critics (2.7), and organisational objectives sit on the client’s strategic scorecard (8.4). Developers must not introduce third-party terminology into code identifiers, database enumerations, user-interface labels, report templates, chart legends or AI prompt text; a deny-list enforces this in the build pipeline (10.7).

#Heading1 1. System Set-up
#Heading2 1.1 Reference architecture
The platform is a multi-tenant web application. Every tenant is one client organisation; PAC itself is a tenant with cross-tenant consulting rights granted per engagement, never globally. The architecture separates four concerns deliberately: response capture, scoring, interpretation and reporting. Scoring must be deterministic and reproducible; interpretation may be probabilistic; the two must never be mixed in the same service.

#Heading3 1.1.1 Advisory meaning
The architectural separation is not merely technical hygiene. PAC’s method rests on the claim that every number in a client report is traceable to the data and reproducible on demand. A consultant challenged in a board meeting must be able to say that the figure was calculated, not generated. Keeping the scoring service free of AI is what makes that claim true.
#Heading2 1.2 Tenant and organisation onboarding
Onboarding has two stages. Stage one records the organisation’s structure, which determines what can be analysed. Stage two is the facilitated Pre-Assessment Executive Workshop, which records strategy, performance, behaviours and the change agenda — the parameters against which all culture findings are later measured. PAC/CDP/INST/001 is explicit that no setup input may be pre-filled by an individual or by the HR function in isolation, and that the platform record is the single source of truth. The platform must enforce this: a setup section cannot be marked complete without a recorded workshop date and at least two named executive participants.

#Heading3 1.4.2 Versioning
Every item, scenario statement, scale and scoring rule is versioned. An assessment record stores the instrument version and the rules version it was scored under, and recomputation must use the stored versions, never the current ones. Item-bank version 1.1 is the canonical UK-English release: one spelling and register across the culture survey and both 360 forms, with a recorded equivalence statement. Version 1.1 is orthographic only and does not alter item meaning, scale anchors or scoring, so it is treated as equivalent to 1.0 for trend comparison. Any future change to item wording that affects meaning creates a new major version and breaks trend comparability; the platform blocks any comparison that crosses a major version boundary and warns across a minor one.
#Heading3 1.4.3 Languages
Setup Section I captures the required languages. UK English is the canonical source and the only language available at first release. Every other language is added per tenant as a locale variant of each item, publishable only after forward translation, independent back-translation and reconciliation by a PAC certified practitioner fluent in the language, with the reconciliation recorded against the item. Respondents choose language at survey start; the choice is stored on the response for analysis but is not a reportable demographic unless the tenant has five or more respondents in that language. Scores from different locale variants of the same item version are pooled; the platform flags any orientation score where one language cohort diverges by more than the sub-culture divergence threshold, because that pattern may indicate a translation defect rather than a sub-culture.
#Heading3 1.4.4 Anonymity thresholds
Three floors operate simultaneously. Any reporting segment for the culture survey requires at least five respondents. Any 360 rater group requires at least three raters, and a group below three is merged into an “all others” group. Any organisational cohort report requires at least five respondents. These floors are absolute: PAC/CDP/INST/001 states that the threshold is maintained without exception regardless of client requests, and the platform must therefore not expose an override to any role.
Response rows are stored without a direct person reference. An invitation record links a person to a single-use token; on submission the response is written against the token’s demographic snapshot and the link between person and token is destroyed. This means the platform cannot reconstruct an individual response even under compulsion, which is what the anonymity commitment in the staff communication actually promises.
#Heading3 1.4.5 Consent and data protection (Kenya Data Protection Act, 2019)
The obligations below implement the Act and its regulations for Kenyan tenants. The client’s data protection officer signs off the tenant’s consent text and processing record before first launch; the sign-off is a launch pre-flight check (10.2). Where a tenant operates outside Kenya, the equivalent local regime applies (for Ethiopian tenants, Ethiopia’s personal data protection proclamation) and the platform records on the tenant which regime governs it.
Obligation
Platform implementation
Lawful basis and consent
Consent is captured per respondent at survey start, before the first item is displayed, as an explicit affirmative action with a timestamped record. The consent text states purpose, categories of data, retention period, recipients and the right to withdraw. Consent is not bundled with employment terms.
Purpose limitation
The assessment purpose is recorded on the tenant and reproduced in the consent text. The platform blocks any export that is not a released report, and blocks any query whose stated purpose differs from the recorded one.
Data minimisation
Only closed-list demographics necessary for the agreed cohort analysis are collected. Setup Section I must name each demographic and its analytical purpose; unnamed attributes cannot be collected.
Sensitive personal data
Gender, age band and any health or ethnicity attribute are treated as sensitive. Collection is optional per respondent, defaults to “prefer not to say”, and a refusal never blocks survey completion.
Data subject rights
Self-service routes for access, rectification of demographic attributes, objection and erasure of the invitation record. Because responses are unlinked at submission, the platform must tell the respondent plainly that a submitted response cannot be retrieved or deleted individually, and the consent text must say so before submission.
Retention and destruction
24 months from assessment completion, then irreversible destruction, unless the client requests an alternative in writing before expiry. Implemented as a scheduled job with a pre-expiry notification at 90 and 30 days and an immutable destruction certificate.
Cross-border transfer
Tenant residency region is enforced at the storage and processing layer. Any transfer outside the region requires a recorded transfer basis; the AI interpretation service must run in-region or receive findings only, never response content.
Processor obligations
PAC acts as processor for client tenants. The platform maintains a processing register, sub-processor list, breach detection and a 72-hour notification workflow to the data controller and the regulator.
Ethical use constraint
PAC/CDP/INST/001 prohibits using CDP findings to make decisions about specific individuals. The platform enforces this by construction: no individual culture response exists, leader reports are marked development-only, and the 360 module blocks export into any performance or remuneration context.
#Heading1 2. Organisational Culture Assessment
#Heading2 2.1 The four orientations and nine dimensions
The CDP measures the relative strength of four culture orientations. Every organisation carries all four simultaneously; the profile reveals which dominate, which are under-represented and how the actual profile compares with what the strategy requires. The orientations are placed on two tensions that are PAC’s own construction: a horizontal tension running from an inward, people-centred focus to an outward, market-facing focus, and a vertical tension running from an adaptive, change-seeking stance to a structured, control-oriented one. Each orientation sits where two poles meet, and each is a legitimate definition of success. Their relative positions are what makes the profile actionable, because they predict which shifts are easy and which are hard.

#Heading2 2.3 Instrument design and response capture
#Heading3 2.3.1 Two perspectives
D1–D6 are completed twice: first for NOW, the organisation as it is today, then for PREFERRED, the culture the respondent believes the organisation needs in five years. Respondents rate the organisation as a whole, not their own team. The gap between the two perspectives is the most analytically valuable output of the instrument and the primary driver of the action plan. D7–D9, eOS and the qualitative questions are single-perspective.
#Heading3 2.3.2 Constant-sum entry control
Each scenario presents four statements labelled ENGAGE, INNOVATE, PERFORM and GOVERN in a fixed orientation sequence, and the respondent distributes exactly 100 points across them. The control must show a live running total, must not permit submission of the scenario while the total differs from 100, must permit zero on any statement, and must accept integers only. Statement order within a scenario is fixed rather than randomised so that the constant-sum trade-off is presented consistently; the orientation label is displayed, because the instrument is a self-report of relative emphasis rather than a disguised test.
#Heading3 2.3.3 Advisory meaning of constant-sum
Constant-sum scoring carries a consequence that must be stated in every debrief: gaining one orientation requires releasing another. A plan that proposes to build ENGAGE without naming what will be moderated is arithmetically incoherent and will fail in practice. This is why every strategic priority in section 8 must name its trade-off.
#Heading2 2.4 Orientation scores
Logic. For each orientation, the orientation score is the arithmetic mean of that orientation’s 18 scenario allocations across D1–D6, computed separately for NOW and PREFERRED and separately for each reporting cohort. Because each scenario sums to 100, the four orientation scores for a given perspective and cohort also sum to 100. Scores are held to two decimal places internally and presented to whole points in client reports. Rounding rule (platform-wide): every rounding step uses half-up decimal arithmetic, never binary floating point and never banker’s rounding, so 3.085 reports as 3.09 (UT-52).
orientation_score(o, perspective, cohort) =    Σ allocation(o, d, s, perspective, r)  for d in D1..D6, s in S1..S3, r in cohort    ÷ (18 × |cohort|)
Dimension-level orientation scores use the same formula restricted to the three scenarios of that dimension, and are required for the lens calculations in 2.10 and the playbook watch-lists in section 6.

#Heading2 2.5 Culture gap
Logic. gap(o) = orientation_score(o, PREFERRED) − orientation_score(o, NOW), per orientation and per cohort. Because both perspectives sum to 100, the four gaps always sum to zero, a property the platform asserts as a unit test. A positive gap means the cohort wants more of that orientation; a negative gap means less. A gap of 8.0 points or more in either direction is strategically significant and requires a named workstream and an executive owner. The full classification is specified at 6.2.

Advisory meaning. The sum-to-zero property is the debrief’s most useful teaching point. A client asking for more of everything has not yet made a strategic choice. #Heading3 2.6.1 Dominant and secondary
The dominant orientation is the highest NOW orientation score; the secondary is the second highest. Where two orientations are within 1.0 point of each other, the platform reports a shared dominance and the report narrative must describe the culture as dual-oriented rather than naming a single dominant orientation. Ties are never broken arbitrarily. The same rule applies to the PREFERRED profile and to every cohort.

#Heading3 2.9.2 Leadership alignment score
This input carries a fifth of the TPS and is defined as follows.
Definition. The leadership alignment score is a single, always-computable figure on the 1–5 scale, blended by 360 coverage so that it never switches construct and never steps discontinuously between assessment cycles.
coverage = Σ headcount_led(leaders with a valid 360 result) ÷ Σ headcount_led(all accountable leaders)
LRI_weighted = Σ (LRI(leader) × headcount_led(leader)) ÷ Σ headcount_led(leader)               across leaders with a valid 360 result
The Leader Readiness Index is on the 1–5 scale (4.6), so this term is directly compatible with D7, D8 and D9.
LA_instrument = 1 + 4 × min(1, D2_NOW[target] ÷ T(target))
Here target is the primary orientation tagged on the target leadership behaviours in Setup Section F (Section F requires exactly one primary tag) and T(target) is that orientation’s single-orientation dominance threshold from 6.3.1.
leadership_alignment = ( coverage × LRI_weighted ) + ( (1 − coverage) × LA_instrument )
Why it is built this way. Three properties matter. It is construct-consistent: both terms measure leadership behaviour against the orientation the strategy requires, so the blend never mixes a readiness measure with a satisfaction measure. It is always computable: at zero 360 coverage the score resolves cleanly to the D2 instrument term, which every assessment produces, so a first-cycle client with no 360 data still receives a TPS. And it is continuous: coverage enters as a weight rather than as a switch, so a client moving from 55% to 65% coverage between cycles sees no artificial step in the headline number.
eOS Q2 is never substituted for leadership alignment. Q2 measures staff perception of leadership quality, a different construct from leadership readiness, and substituting it at a coverage threshold would make consecutive cycles non-comparable and create a discontinuity in the TPS trend that has nothing to do with the culture.
Reporting rules. The coverage figure is displayed wherever the TPS is displayed. Below 60% coverage the TPS is labelled provisional, and the report states the coverage percentage and that the instrument term is carrying most of the weight. At zero coverage the report states that no 360 data exists for the cycle and that leadership alignment is derived entirely from D2. The provisional label is presentational only: it is never an input to a gate or a calculation.
Worked-example value. The illustrative cycle carries no 360 data, so coverage is zero and leadership_alignment resolves to LA_instrument. The target orientation is ENGAGE (Setup Section F names coaching and listening), with a dominance threshold of 30. The illustrative D2 NOW allocation to ENGAGE is 18.0, giving 1 + 4 × (18.0 ÷ 30) = 3.40, from which the TPS of 3.09 follows. The D2 value of 18.0 is a test fixture consistent with the rest of the illustrative profile (ENGAGE 22 overall; D2 PERFORM-dominant) and describes no real organisation.

#Heading1 3. Sub-culture Assessment and Slice-and-Dice Analytics
#Heading2 3.1 Purpose
An organisation-wide profile is an average, and averages conceal the thing PAC is usually hired to find. The sub-culture engine exists to answer three questions: where in the organisation is the culture materially different from the whole; where do executives and staff see two different organisations; and which of those differences matters enough to fund an intervention.
#Heading2 3.2 Segmentation model
Any dimension captured on the respondent’s demographic snapshot is a segmentation axis, and any combination of axes is a valid segment subject to the suppression rules in 3.6. Standard axes are division, department or function, location or site, grade or level band, executive flag, tenure band, age band, gender, contract type, survey language and any tenant-defined custom attribute.
A segment query is defined as a set of axis–value predicates combined with AND. The engine resolves the segment, counts distinct valid responses, applies suppression, and only then computes. Every metric in section 2 is computable for any permitted segment: orientation scores for NOW and PREFERRED, gaps, dominance, strength, congruence, D7–D9, eOS categories and Index, and TPS where a leadership alignment input exists for the segment.
#Heading2 3.3 Detecting a sub-culture
The rules below extend the 8-point significance principle from the organisation-wide gap to segment comparison.
Sub-culture Divergence Index:
SDI(segment) = Σ | orientation_score(o, NOW, segment) − orientation_score(o, NOW, organisation) |  over the four orientations               ÷ 2
Because both profiles sum to 100, the sum of absolute differences is always twice the share of the profile that has moved between orientations. Dividing by two therefore expresses the SDI directly as the percentage of the culture profile that differs from the organisational profile, on a 0–100 scale.

The executive cohort is defined by the grade flag set during onboarding (1.2.1); the staff cohort is every respondent not so flagged. Both cohorts must independently meet the five-respondent floor or the perception gap is not computed at all, and the report must say so rather than showing a blank.
Advisory meaning. A gap above seven points means executives are operating with a fundamentally different picture of cultural reality from the staff who work inside it daily, and PAC’s position is that such gaps are often more strategically consequential than the culture profile itself. The direction matters for the conversation even though it does not change the threshold: executives seeing more ENGAGE than staff report is a leadership blind spot about care, while executives seeing less GOVERN than staff report is a blind spot about bureaucracy. In the worked example both occur simultaneously — executives see ENGAGE at 30 against staff at 19, and GOVERN at 22 against staff at 33 — which means staff experience a bureaucratic, target-driven organisation that its leaders do not believe they run.

#Heading2 3.6 Anonymity protection on small groups
Six rules operate together, and none is overridable by any role.
Rule
Specification
Primary floor
No culture-survey segment is reported unless it contains at least five valid responses. 360 rater groups require at least three raters, with a group below three merged into “all others”.
Combination floor
A segment built from two or more axes must independently satisfy the five-respondent floor. The engine evaluates the resolved intersection, not the individual axis counts.
Differencing protection
A segment is suppressed if it can be derived by subtracting one reported segment from another reported segment and the residual would fall below the floor. In practice the engine suppresses complementary pairs: if a department has 22 respondents and one of its two teams has 18, the second team is suppressed and so is the first, because publishing one discloses the other.
Small-cell rollup
Suppressed segments are automatically merged upward into the nearest parent that satisfies the floor, and the report labels the rollup explicitly. Merged content is never silently dropped.
Qualitative suppression
Verbatim extracts require at least eight valid qualitative responses in the segment and are published only as themes with counts, never as quotations attributable to a segment of fewer than eight.
Query audit
Every segment query is logged with actor, predicates, resolved count and suppression outcome, so that an attempt to triangulate a small group is detectable after the fact.
Advisory meaning. The floors are frequently tested by clients who want to know what one small but troublesome team thinks. The answer PAC gives is that the commitment made to respondents is what makes the data worth having, and that a diagnosis of a five-person team is a management conversation, not a culture assessment. The platform’s refusal to answer is therefore a feature to be explained, not a limitation to be apologised for.

#Heading2 4.2 Scoring logic
All section scores are converted to an average item score on the 1–5 scale, because the sections have different item counts and raw totals are not comparable.
average_item_score(section) = section_total ÷ item_count(section)
For sections A–D this is the total divided by 10; for sections E–H it is the total divided by 5. Every threshold in this section operates on the average item score, never on the raw total.
Rater scores are averaged per item and per section, by rater group (superior, peers, direct reports) and overall. The overall other-rating is the unweighted mean of the available rater groups, so that a single superior does not carry the same weight as eight direct reports collapsed into one group average. Where a rater has selected “not observed” on an item, that item is excluded from that rater’s section mean and the section mean is computed on observed items only; a section with fewer than three observed items for a rater is excluded from that rater’s contribution.

#Heading2 4.7 Anonymity in the 360
A rater group is reported only with at least three raters; a group of one or two is merged into an “all others” group, and if that merged group still has fewer than three raters no rater-group breakdown is published at all — only the overall other-rating. Individual rater responses are never exposed to any role. Qualitative comments are released to the leader only after consultant review for identifying content, and the platform must support redaction of a comment while retaining the original in the encrypted store.

#Heading2 5.2 Leader–culture fit index
The fit index measures how closely the leader’s own behavioural profile matches the culture their team actually has. It is a measure of congruence, not of quality: a high fit with an unhealthy culture is a problem, not a strength.
Convert the leader’s four A–D average item scores into a comparable profile by normalising them to sum to 100:
leader_profile(o) = A_D_average(o) ÷ Σ A_D_average(all four) × 100
fit_index = 100 − ( Σ | leader_profile(o) − team_profile_NOW(o) | ÷ 2 )
The index runs from 0 to 100, where 100 means the leader’s behavioural emphasis exactly mirrors the team’s culture. The divisor of two makes the subtracted term the percentage of profile that differs, exactly as in the SDI at 3.3, so the two indices are read on the same scale.

#Heading1 6. Scenario-Based Reporting and the Guidance Engine
#Heading2 6.1 Structure of the engine
The guidance engine is a deterministic rules evaluator. It takes the scored assessment, evaluates a versioned rule set, and emits findings. A finding is a structured object — not prose — carrying a diagnosis, a severity, the evidence that produced it, the risks it implies, the root-cause hypotheses to test in the debrief, and a set of candidate actions across three horizons. Prose is generated later, from findings only, by the interpretation service described at 6.12, after the report composer (section 12) has selected and filled the suggestions.
The engine runs in a fixed order, because later rules depend on earlier classifications: gap classification, then the four alignment checks, then the perception-gap and engagement flags, then the readiness gates, then pathway selection, then scenario matching, then action generation and prioritisation.

#Heading3 6.3.2 Alignment percentage and verdict (C1 and C4)
For the set R of orientations the strategy or business model requires, with threshold T(r) for each:
sub_alignment(r) = min(100, 100 × NOW(r) ÷ T(r))alignment_pct    = mean(sub_alignment(r) for r in R)
Verdict from the published bands: alignment_pct ≥ 80 is a HIT; 60 to &lt; 80 is a PARTIAL HIT; &lt; 60 is a MISS. Two overrides then apply, in order:
Override 1 — if any r in R has a NOW(r) that does not exceed T(r), the verdict cannot exceed PARTIAL HIT. Override 2 — if any r in R is the lowest-scoring orientation in the NOW profile, the verdict is MISS. Override 2 does not apply to the balanced business-model transition requirement: there every orientation is required, so the lowest is always in R, and override 1 alone caps the verdict (UT-17, UT-51).
Worked example, C1. The strategy is digital channel growth, so R = {INNOVATE}, T = 28, NOW = 14. sub_alignment = 100 × 14 ÷ 28 = 50.0, so alignment_pct = 50.0, which is below 60 and therefore a MISS. Override 2 confirms it: INNOVATE is the lowest NOW score. Verdict: C1 MISS — the digital growth strategy requires INNOVATE above 28 and INNOVATE is the weakest orientation in the organisation.
Worked example, C4. The declared business model is service (B2C), so R = {ENGAGE, PERFORM}, with thresholds 30 and 30, and NOW scores 22 and 34. sub_alignment(ENGAGE) = 73.3; sub_alignment(PERFORM) = min(100, 113.3) = 100.0; alignment_pct = 86.7, which alone would read as a HIT. Override 1 applies because ENGAGE at 22 is below its threshold of 30, so the verdict is capped. #Heading3 6.3.4 Behaviour gap verdict (C2)
C2 uses both rank and magnitude, with a strict division of labour: rank determines the verdict, magnitude determines the intervention intensity, and magnitude can never change the verdict. Rank drives the verdict because C2 asks whether the target orientation dominates leadership practice, which is a dominance comparison, not a distance. But rank alone is lossy: a target orientation sitting second at 27 against a dominant 28 is a materially different problem from one sitting second at 27 against a dominant 45, and an engine that reported both as PARTIAL HIT would send the same recommendation to two organisations that need different programmes.
Let target be the orientation tagged on the target leadership behaviours in Setup Section F, and let the leadership practice profile be the orientation scores of the Leadership lens (D2) combined with D3 People Architecture, since both measure what staff actually experience.

#Heading2 6.7 Priority selection rules
Rule
Specification
Strategy before size
An orientation classified BUILD that is also a C1 or C4 miss outranks a larger gap the strategy does not need. Sort order is: C1/C4 miss first, then C2 miss, then C3 systemic miss, then gap magnitude.
Maximum four
No more than four strategic priorities, normally one per orientation, capped further by the readiness gates.
Pair every BUILD with a MODERATE

Every priority carries one visible change within 30 days, preferably to a recognition ritual.

#Heading3 6.10.1 Alignment verdict sub-routine
FUNCTION alignment_verdict(required, now, balanced):    IF required IS EMPTY THEN RETURN NOT_APPLICABLE    subs = [MIN(100, 100 * now[r] / threshold(r)) FOR r IN required]    pct  = MEAN(subs)    IF   pct &gt;= 80 THEN verdict = HIT    ELIF pct &gt;= 60 THEN verdict = PARTIAL_HIT    ELSE               verdict = MISS    # Override 1: a required orientation that does not exceed its threshold    IF ANY r IN required WHERE now[r] &lt;= threshold(r):        verdict = MIN(verdict, PARTIAL_HIT)    # Override 2: a required orientation is the weakest in the profile    #             (not applied to the balanced transition requirement)    IF NOT balanced AND ANY r IN required WHERE r == argmin(now):        verdict = MISS    RETURN verdict, pct

#Heading2 6.12 The AI interpretation panel
The AI interpretation panel turns findings into readable narrative for the consultant to review, adapt and present. It is an assistant to the practitioner, never a substitute for one: PAC’s method requires that all reports be presented by a trained facilitator or certified practitioner and that raw scores are never shared without contextual interpretation. The panel therefore produces draft narrative that a named consultant must accept before it can appear in any released report.
#Heading3 6.12.1 What the panel receives
The panel receives a structured findings payload only: computed scores, classifications, check verdicts, flags, gate outcomes, matched scenarios with their published diagnoses and hypotheses, selected priorities with pathways, and the relevant setup parameters. It does not receive individual responses, verbatim qualitative text, respondent counts below the anonymity floor, or any personally identifying attribute. It receives thematic summaries of qualitative data, produced by a separate extraction step that is itself subject to the suppression rules at 3.6.

#Heading3 6.12.3 Prompt design
The system prompt is fixed, versioned alongside the rules engine, and contains five blocks. First, the role: a PAC culture analyst drafting narrative for a certified practitioner’s review. Second, the vocabulary constraint: the only permitted terminology is the CDP terminology in the glossary at 10.8, and no third-party framework, quadrant name, instrument name or brand term may appear. Third, the grounding rule: every sentence that makes a claim must be traceable to a supplied finding, and the draft must carry an inline reference to the dimension, check or category that supports it. Fourth, the refusal rule: where the findings do not support a requested statement, the panel says so rather than generating one. Fifth, the output contract: a fixed JSON structure with one field per report section, so the renderer never parses free prose.
The user prompt is assembled by the platform from the findings payload and carries no consultant free text into the model other than a bounded “emphasis” field, which may select which finding leads but may not introduce content.
#Heading3 6.12.4 Guardrails and verification
Guardrail
Implementation
Numeric integrity
Every number in the generated narrative is matched against the findings payload before rendering. An unmatched number blocks the draft and raises an error to the consultant. The panel does not get to be approximately right about a score.
Terminology screen
A deny-list of third-party framework, instrument and brand terms is applied to every draft. A hit blocks the draft and logs the term. The deny-list is maintained by PAC and versioned with the prompt.
Claim traceability
Each generated statement carries its supporting reference. A statement without a reference is stripped before the consultant sees it, and the strip is logged.
Causal-language screen
A pattern screen rejects causal constructions (“because”, “caused”, “drove”, “resulted in”) linking a culture score to a business outcome, and offers the associational form instead.
Individual-attribution screen
Any draft naming an individual, or describing a group small enough to identify one, is blocked.
Human acceptance
No generated narrative reaches a client role until a named PAC Consultant accepts it. The acceptance is recorded with the consultant’s identity, the prompt version and the model version, so any released report can be reconstructed.
Determinism of the number, not the prose
The same assessment always produces the same scores and the same findings. The narrative may vary between drafts, and the platform must therefore never treat generated prose as a stored fact or re-use it as an input.
Advisory meaning. The panel exists to save the consultant the first hour of writing, not the judgement. PAC’s credibility rests on the claim that the number was calculated and the interpretation was made by a qualified practitioner who can be questioned about it. The guardrails above are what allow that claim to survive contact with a sceptical board.
#Heading1 7. Reports — Conclusive and Guiding
#Heading2 7.1 Common rules for every report
Every report in the suite obeys four rules. It states a conclusion, in a section headed “What this means”, written as a judgement rather than a summary. It states a recommendation, in a section headed “What to do next”, naming an owner and a date. It carries the technical appendix: response rates, exclusions, suppression notes, instrument and rules versions, and the definition used for any substituted input. And it is released only by a certified practitioner, with the release recorded.
A report that presents scores without a conclusion is not releasable. This is a platform rule, not a style preference: the release action is blocked until both mandatory sections contain content.

#Heading2 7.5 Leader and leadership-team reports
Content is specified at 5.5 and 5.6. Three presentation rules are additional. A leader report is delivered in a facilitated conversation, never by unaccompanied email, and the platform’s default distribution therefore notifies the coach rather than releasing the document. Hard flags are stated in plain language without euphemism, because a softened integrity finding is worse than none. #Heading1 8. Action Planning Module
#Heading2 8.1 Principle
The module exists to close the distance between a finding and a commitment. Its design principle is that the platform drafts and the humans decide: the guidance engine produces draft actions automatically so that the Action Planning Workshop spends its time on choices rather than on blank templates, but no draft becomes a commitment without a named owner, a date, a measure and an approval.
#Heading2 8.2 From findings to draft actions
Each selected priority generates draft actions at three levels. The level determines the scope, the owner role and the default horizon.

Generation logic. For each priority, the engine selects candidate actions from the orientation playbook’s action set, filters them by the horizons permitted by the readiness gates, and instantiates each with the priority’s linked finding, the affected orientation, the default owner role and a review point. Every draft is created in DRAFT status and is explicitly labelled as machine-generated until a consultant has reviewed it. The engine never assigns a named individual, a budget figure or a target value; those three fields are always human-entered, because they are commitments rather than inferences.
Mandatory companions. Every priority’s generated set must contain at least one quick win dated within 30 days and marked as the visible signal, at least one action touching a system lever in the medium-term or structural horizon, and, for every BUILD priority, one action that gives effect to the named trade-off. The engine refuses to emit a set missing any of the three.

#Heading2 8.8 Measuring impact
Mechanism
Specification
Pulse surveys
Short instruments drawn only from the priority’s CDP re-measurement watch-list: the named D-dimension scenarios, the named eOS categories, and nothing else. Maximum 10 items, run at 90 and 180 days, to a sample or a cohort. Pulse results are indicative and are never substituted for a full assessment score, and the platform labels them accordingly.
Re-assessment triggers
Scheduled annually as the default. Triggered earlier by any of: completion of all structural actions on a priority; a material organisational change (restructure, merger, new CEO, business-model transition going live); a pulse showing a watch-list item moving more than 0.5 on a Likert dimension or more than 15 points on an eOS category; or a board request.
Before-and-after comparison
Orientation scores, gaps, classifications, D7–D9, TPS, LRI distribution and eOS categories, compared to the baseline assessment at organisation and segment level. Comparison is blocked across an instrument major version boundary and warned across a minor one.
Attribution discipline
The platform reports movement, not causation. Where a watch-list item has moved and the linked actions were delivered, the report states both facts and their coincidence. It does not state that the action caused the movement, and the AI panel is screened for causal language (6.12.4).
Trade-off verification
Because the profile is constant-sum, a successful BUILD must show a corresponding reduction elsewhere. The platform checks whether the reduction landed on the named trade-off orientation or somewhere unintended, and reports the difference. An unintended release is one of the most useful findings a re-assessment produces.

Facilitated perception-gap workshop before anything else; unfiltered upward listening route; middle-manager sensing routine; re-measure the gap at the next pulse.
Perception gap per orientation; eOS Q5; participation in listening routes.
Executives publish, unedited, the three things staff said that they had not expected.
SC-06 Sub-culture divergence
Decide explicitly whether to align the unit, protect it, or learn from it.

SC-07 Leader misaligned with a healthy team
Protect the team while the leadership question is addressed.
Leader development plan with a named coach; sponsor one level up takes the unit’s culture priority; 360 re-measure at 180 days; retention conversations with key team members.
Leader fit index; self–other gap on the BUILD section; team eOS differential; team attrition.
The leader commits publicly to one observable behaviour change their team will see within 30 days.

Remove the constraint rather than develop the leader.
Decision-rights review; resourcing review; dependency mapping to adjacent units; parent-unit culture check.

Build the capacity to change before naming what to change.
Change infrastructure: sponsorship, resourcing, clarity of expected behaviours, lessons-learned discipline; psychological safety workstream where D8 ≤ 3.0; one or two priorities maximum.

Close out, publicly and honestly, the last change programme that was never formally ended.
SC-10 Systems fighting the strategy
Stop paying for the behaviour the organisation says it wants to stop.
HR systems redesign within 90 days across performance management, promotion, incentives and onboarding; change one recognition ritual within 30 days.
Promotion decisions against the stated criteria; incentive mix; eOS Q7; D6 at re-assessment.
Change one visible recognition ritual and explain the change in the same announcement.
SC-11 Everything at once
Make the strategic choice the profile has avoided.
Return to Setup Sections B–D with the executive team; select one orientation as the primary build and name its trade-off; defer the rest visibly to the backlog.
Alignment percentage on C1; number of active priorities; gap on the selected orientation.

Protect what is working against growth and succession.

Advisory meaning. The governance design answers the commonest failure mode in culture work, which is that the programme is delegated to HR and interpreted by staff as an HR initiative rather than a strategic one. Three features prevent that reading: the CEO owns priority zero and delivers the visible signal personally, every priority has an ExCo sponsor by name, and the board receives the eOS and TPS trend as a standing item. Culture findings must never be used to make decisions about specific individuals, and the governance minutes record that constraint at the first meeting of the cycle.

#Heading2 11.2 When the reference is used
Results debrief: interpreting the orientation profile and gaps with the executive team.
Action Planning Workshop: a facilitated session of one to one and a half days in which leaders agree up to four strategic culture priorities and complete the templates in 11.12, working directly in the platform.
Cascade sessions: departments and teams translating the organisation-level plan into their own commitments using the interaction matrices.
Progress reviews: 30, 90 and 180-day checkpoints, and the annual CDP re-assessment.
Core principle. Culture change is a trade-off, not an addition. Resources, attention and leadership time are finite, and starting something new almost always means scaling something else back. Every priority in the action plan therefore names what the organisation will do more of, less of, start, stop, and keep and protect.

#Heading2 11.4 Complementary and contrasting relationships
Each orientation shares one pole with each of its two neighbours and none with its diagonal opposite. This predicts where collaboration comes easily, where friction will arise, and how hard a given shift will be.
Pair
Shared ground
What it means for action planning
ENGAGE + INNOVATE (top)
Adaptive pole: openness to change
Both are comfortable with unorthodox structures and a long-term horizon. ENGAGE invests in people and knowledge; INNOVATE invests in ideas, ventures and new capability.
PERFORM + GOVERN (bottom)
Structured pole: discipline and order
Both rely on formal structures and measurement. GOVERN measures process and quality as the route to results; PERFORM measures financial and delivery results directly.
INNOVATE + PERFORM (right)
Outward focus
Both aim for market leadership. INNOVATE gets there through ideas and agility; PERFORM through focus, cost discipline and competitive drive.
GOVERN + ENGAGE (left)
Inward focus
Both build systems for continuous improvement and learning. ENGAGE focuses on people (feedback, development); GOVERN on processes (after-action reviews, standards).
ENGAGE ↔ PERFORM (diagonal)
None: contrasting priorities
People and relationships against results and pace. Typical symptom: “we care about our people” colliding with “hit the numbers”. Addressed in CDP Check C2.
INNOVATE ↔ GOVERN (diagonal)
None: contrasting priorities
Freedom to experiment against control and compliance. Typical symptom: “move fast” colliding with “follow the process”. Addressed in CDP Check C2.
Planning implication. Shifts between neighbouring orientations are easier than shifts across the diagonal. When the PREFERRED profile demands a diagonal shift and the TPS is below 3.50, or D8 or D9 is at or below 3.0, the shift is planned in two moves through a stepping-stone orientation (6.5.1).

#Heading2 11.6 Hits &amp; Misses: quick reference for action planning
The CDP tests culture against strategy through four checks (6.3). Each compares a different part of the result with what the organisation says it needs (its targets, its stated leadership intent, its change agenda and its business model) and returns HIT (aligned), PARTIAL HIT (broadly aligned, with a named gap) or MISS (the culture is working against the strategy). A MISS is the strongest trigger for a strategic priority. Each check is read alongside the gap classification (6.2), and the readiness gates (6.6) then set the pace.

C1 Performance alignment compares the dominant orientation with the orientation the KPI targets require. A miss means the culture is optimised for results the strategy is not asking for, as when a digital growth strategy needs INNOVATE above 28 in an organisation where INNOVATE is the lowest NOW score. The playbook metrics tables name the performance shortfall the gap is producing.
C2 Behaviour gap compares what leaders model, as staff experience it (D2 Leadership Blueprint and D3 People Architecture), with the behaviour the organisation says it wants. A miss usually surfaces with an executive–staff perception gap, and the levers are leadership development, 360-degree feedback and leadership KPIs rather than communication.
C3 Stop / start audit tests whether the bonding mechanisms and success definitions (D4 Cohesion Drivers and D6 Victory Conditions) reinforce the change agenda or quietly contradict it. Recognition rituals, scorecards and reward are the usual culprits, which is why every playbook carries a visible signal delivered within 30 days.
C4 Business-model readiness asks whether the culture can deliver the business model the organisation is running or planning. A miss is a longer-horizon finding (6–18 months, CEO and ExCo) and normally calls for a multi-orientation shift using the pathways in 6.5.

#Heading2 11.14 Ethical use in action planning
Action plans address organisational culture, never individuals. No cohort below the reporting floor is reported (3.6). #Heading1 12. Report Composition Engine
#Heading2 12.1 Principle
The platform writes complete reports, with suggestions that fit the organisation in front of it, by joining three things it already holds: the findings the rules engine produces (section 6), the reference library built from the action planning content in section 11, and the report templates in sections 3, 5, 7 and 8. A fourth component, the composition engine specified here, selects the right library entries for each finding, fills them with the organisation’s own numbers, KPIs and names, and assembles every section of every report.
Three rules govern it, in the same spirit as the separation of scoring and interpretation (1.1):
The engine selects; it never invents. Every suggestion in a report is a reference-library entry chosen by a deterministic, explainable fit score, and carries the finding and the entry that justify it.
The AI panel phrases; it never chooses. The panel may rewrite, shorten and sequence the selected content for the audience. It may not add a suggestion, drop a mandatory one, or change a number (6.12).
The practitioner decides. A composed report is a complete draft. A PAC Consultant reviews, edits and releases it, and every edit is recorded against the suggestion it changed.
Because selection is deterministic, a report can be composed in full even with the AI panel switched off: the template sentences in 12.7 produce a complete, releasable draft, and the panel only improves its prose.

#Heading2 12.3 Selecting fitting suggestions
Selection runs once per priority and once per report section that carries suggestions. It has two stages: hard filters that remove entries that do not apply, then a fit score that ranks the rest.
#Heading3 12.3.1 Hard filters
An entry is excluded if any of the following is true:
Filter
Rule
Orientation and direction
Entry orientation and direction do not match the priority (or the trade-off, for moderate entries).
Mandatory trigger
Any trigger marked mandatory is false, e.g. a D7 adoption-plan entry when D7 &gt; 3.0.
Gate
The entry’s horizon or level is not permitted by an open readiness gate (6.6); content entries are excluded while a blocking gate on the orientation is open, leaving only priority-zero entries.
Readiness ceiling
Effort exceeds the ceiling for the TPS band by more than one point. Ceilings: HIGH RISK 2, ENABLEMENT REQUIRED 3, TARGETED SUPPORT 4, STRONG READINESS 5.
Context
The entry carries context tags and none matches the tenant’s sector or business model.
History
The same entry was retired with outcome “not achieved” in this tenant in each of the last two cycles.
Status
Entry is not approved, or belongs to a library version other than the one pinned to the assessment.
#Heading3 12.3.2 Fit score
fit = 0.30 × trigger_match      # share of the entry's supporting triggers that are true    + 0.20 × scenario_match     # 1 if linked to a matched scenario (6.8), else 0    + 0.15 × kpi_link           # 1 if a kpi_ref matches a Setup C/D strategic KPI on this orientation, else 0    + 0.15 × readiness_fit      # 1 if effort ≤ ceiling, 0.5 if one point above    + 0.10 × context_fit        # 1 if a context tag matches, 0.5 if the entry is untagged    + 0.10 × history_fit        # 1 normally; 0 if retired “not achieved” in this tenant last cycle
All six terms are on 0–1, the weights sum to 1.00 and are asserted in code, and the score is held to two decimals with half-up rounding. Ties break on lower effort, then on entry_id, so the same assessment always yields the same suggestions in the same order.
#Heading3 12.3.3 Assembling a suggestion set
For each priority the engine builds the set in this order, stopping at the caps in 8.3.1:
Mandatory entries first: gate-driven entries (for example the psychological-safety workstream when D8 ≤ 3.0), the stepping-stone entry for a routed diagonal shift, and the mandatory actions of every matched scenario template.
The visible signal: the highest-fit visible_signal entry; exactly one per priority.
The trade-off action: the highest-fit moderate entry for the named trade-off orientation.
Coverage by level: the highest-fit entry at each of leader, team, unit and organisation level not yet covered, so the four-level commitment matrix (11.12.3) is never empty.
Coverage by lever: if no selected entry touches a system lever in the medium or structural horizon, the highest-fit system_lever entry.
Remaining capacity: further entries in fit order until the cap.
Each selected suggestion is stored with its fit score, the triggers that matched, the entries it outranked and the reason for any exclusion, so the consultant can see in the review screen why the engine proposed it and what it considered instead.
#Heading3 12.3.4 Slot filling
Slots are filled only from the scored assessment, the findings and the setup record: orientation names, gaps, unit names, KPI names, baselines and targets from Setup Sections C and D, owner roles from the urgency tier, dates from the review cadence. A slot with no source value is left as a highlighted field for the workshop to complete; the engine never fills a named owner, a budget or a target value it has not been given (8.2).

#Heading2 12.5 Composing the narrative
The composition engine produces, for every report section, a structured section object: the deterministic tables and charts, the selected suggestions with their filled text, and a template draft of the narrative written from fixed sentence patterns. That object is the complete input to the AI panel (6.12.1).
The panel returns the section in the fixed JSON contract with, for every sentence, the finding ids and entry ids it relies on. The guardrails in 6.12.4 apply in full, plus two specific to composition:
Guardrail
Rule
Suggestion integrity
The set of entry ids cited in the panel’s output must equal the selected set. A missing mandatory entry or an extra entry blocks the draft.
Wording drift
Rephrasing is permitted; changing the action, owner role, horizon, lever or KPI of a suggestion is not. The platform compares the structured fields, not the prose.
If the panel is unavailable, times out or is blocked by a guardrail, the template draft is used as it stands. Reports therefore never wait on, and never depend on, the AI panel.

#Heading2 12.7 Learning from outcomes
When an action closes, its outcome (achieved, partially achieved, not achieved, superseded; 8.4) is recorded against the library entry it came from, together with the TPS band, sector and orientation context. The platform reports, to PAC faculty only, each entry’s outcome rate by context, with the number of closures behind it. This is an association record, never a causal claim (8.8).
The fit score uses outcomes in only one way: an entry retired “not achieved” in the same tenant loses its history_fit in the next cycle, and is excluded after two such cycles (12.3.1). Cross-tenant outcome rates never change ranking automatically. Faculty review them each quarter, and an entry with at least 20 closures and a not-achieved rate above 60% in a context is reviewed for rewording, re-tagging or retirement. Changes are released as a new library version.
