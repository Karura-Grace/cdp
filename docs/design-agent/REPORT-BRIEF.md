# CDP report template: brief for the PAC Design Agent

**Owner:** Imran Issa, PAC Africa
**Date:** 3 November 2026
**Status:** Brief for the design agent. Base system rule 1 (Colour) is locked; rules 2 to 6 are still to be built. This brief asks for the report template on top of that base.

## 1. What we need

One complete, empty report template, designed once, that every CDP report is poured into from now on. The platform (CDP) outputs data; the template decides how every page looks. Nothing in a report is designed again for a new client.

The template covers the whole report, every page type, and the three other outputs that share its look: the executive brief (about 7 pages), the PowerPoint deck and the staff facilitation guide.

Target length of the full report: **40 to 50 pages** (Geminia reference: 33; our last draft: 80, which was too long).

## 2. Why the last draft failed (read this first)

The owner's review of our previous draft (DRAFT7):

- It **explains terms more than it reports findings**. Every chapter opens with definitions and "how to read" boxes. About 22,800 words in 80 pages; the reference report has about 7,200 in 33.
- It is **full of text and lacks graphics**. Most data pages have one chart and a lot of prose.
- It **looks like AI slop**: the same sentence frame repeated per dimension, advice that could apply to any company, walls of text, and pages that are mostly empty.
- It **does not explain the findings**. A number is shown but not what it means for this organisation.
- The words "In short" must never be used as a heading.

The look of the reference report (Geminia, see `reference/geminia-*.png` and `REPORT-DESIGN-COMPARISON.md`) is the layout target: heading, visual, table, one short finding box, dense full pages. Copy the layout ideas only. Do not copy its colours, wording, logo, photo or its third party framework names.

## 4. Page frame and rules for every page

- A4. The agent decides margins, grid and spacing and states them in points.
- Running header and footer on every inner page, including client name, report title, page number and a confidentiality line. The PAC logo appears in the header (use the supplied file only).
- A faint diagonal watermark is optional; the owner finds it hurts dense pages, so default it off and make it a switch.
- **Page fill:** no page below about 60 percent filled unless it ends a chapter. Content blocks must be designed so a short or a long data set still fills pages well (see section 8).
- **Two charts per row** where space allows, in surface panels with a bold caps title and a legend (owner Q-D8-4). Full width only for diverging bars and grouped bars.
- Contents page: big "Table of Contents" title, number tiles, sub sections with dotted leaders and page numbers.
- Chapter opener: number tile plus a full width bar with the title in caps. Seven part dividers are optional.
- Cover, About page and back page are designed too (cover facts block: respondents, assessment date, instrument; back page contact block: Suite E2, 1st Floor, Jasmine Centre, Westlands, Nairobi. info@pac.africa. www.pac.africa).

## 6. How every finding is written

Four short lines per finding (owner Q-D8-14), in this order:

1. **Finding:** what we found, with the number.
2. **Evidence:** how we know: which groups, which gap, which score.
3. **Consequence:** what it risks for this organisation if nothing changes.
4. **Action:** the first move, with owner and time.

Design a "finding card" block for this (icon, verdict word, number, four lines) and a one line "so what" callout.

## 7. Writing rules for everything on a page

- Number first. Say what the data shows, then what it means. No definitions in chapters: definitions live in the glossary; one short caption under a chart at most.
- Never use "In short" as a heading. Name AI drafted readings "Findings".
- No repeated sentence frames across items (for example "Here Govern leads at 34.5 points, while the culture overall leads with Perform" once per dimension). Lines must vary with the result.
- Advice only when it cites this client's number. Generic advice is dropped, not shown.
- No dashes or hyphens in prose; business friendly English; no AI sounding phrases. "Culture Practitioner", never "PAC Practitioner".
- Use PAC terms only: Engage, Innovate, Perform, Govern. Do not use third party framework or instrument names (platform specification section 0.2).
- Never expose scoring formulas or weights on a client page.
- Fictional data only in samples.

## 9. Spec chart rules to honour (platform specification section 4.7)

- Profile: grouped bars in fixed orientation order; Now as a light tint with outline, Preferred solid; values on bars; neutral 25 point line; never stacked.
- Gap: horizontal bars from zero with classification bands shaded and the class named at the right; negative gaps shown with equal prominence.
- Perception gap: dumbbell, executive filled circle, staff hollow diamond, gap value and flag at the right; only when both groups have at least five answers.
- Employee voice: diverging bars, negatives red, positives blue, Index as a dashed line.
- 360 self vs others: dumbbell per section, 3.00 flag line.
- Heatmap: diverging scale centred on zero, marked from plus or minus 8.
- Identity never relies on colour alone: every series direct labelled or in a legend; verdicts carry icon and word.

- **PowerPoint deck:** same tokens; charts are native chart objects so a consultant can adjust emphasis.
